Prepare the Pi

Clean-install validation on fresh Raspberry Pi OS is pending. Use a spare Pi or SD card for testing.

  1. Use Raspberry Pi Imager to write Raspberry Pi OS Lite (64-bit). Configure SSH, network access and a user with sudo access. The commands below use pi as the example user.
  2. Give the Pi a unique hostname and reserve its address on the router. Use a separate address while an existing controller is online.
  3. Have the HTTPS hostname or IP and permitted LAN subnet ready. For example, a controller on 192.168.1.0/24 can allow clients on that subnet.

Run the repository installer

Choose a stable tag and full commit from the reviewed GitHub release notes. Replace both placeholders in this single command and paste it as the controller user. The command fetches the exact tag, checks the Git objects and commit, then runs the verified installer.

bash -c '
set -euo pipefail
release=$1
commit=$2
[[ $release =~ ^v(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)$ ]]
[[ $commit =~ ^[a-f0-9]{40}$ ]]
(( EUID != 0 ))
if ! command -v git >/dev/null; then
  sudo apt-get update
  sudo apt-get install -y git
fi
work=$(mktemp -d)
trap "rm -rf -- \"\$work\"" EXIT
ref=refs/tags/$release
git -C "$work" init --quiet
git -C "$work" fetch --depth=1 --no-tags \
  https://github.com/RLF62/hp6033a-web-controller.git "$ref:$ref"
actual=$(git -C "$work" rev-parse "$ref^{commit}")
[[ $actual == "$commit" ]] || { echo "Release commit mismatch" >&2; exit 1; }
git -C "$work" fsck --strict --no-dangling
git -C "$work" checkout --quiet --detach "$actual"
case ${3:-install} in
  install) bash "$work/install.sh" ;;
  update)
    url=${4:?Supply the existing HTTPS URL}
    bash "$work/update.sh" --release "$release" --expect-commit "$commit" --url "$url" "${@:5}"
    ;;
  *) echo "Choose install or update" >&2; exit 2 ;;
esac
' _ '<stable-tag>' '<full-commit-from-release-notes>'

Enter the address and allowed subnet. Accept the default password protection or choose password-free control for a trusted LAN without internet exposure. Create the separate controller credentials in either mode. They are always required to change the password policy from Setup.

The installer configures the service, USB permissions, and Nginx. It verifies the HTTPS status endpoint and Setup on both dashboards before enabling startup. Use the HTTPS URL it reports. The supplied certificate is self-signed. Verify the address and trust the correct certificate on your clients before submitting credentials.

Connect the supply and configure VISA

  1. Reconnect the UsbGpib V2 adapter after the udev rules are installed. Open a fresh SSH session after any change to the user's plugdev membership.
  2. With the output off, list USB VISA resources from the installed environment.
cd ~/hp6033a
venv/bin/python -c "import pyvisa; print(pyvisa.ResourceManager('@py').list_resources())"
nano config.json
sudo systemctl restart hp6033a

Set gpib_resource in config.json to the matching USB VISA resource before restarting. Check /api/status and confirm that GPIB is connected and the readings match the front panel.

Upgrade an existing controller

For a first migration, use the verified download command above and append update https://YOUR_CONTROLLER --dry-run after the commit argument. Remove --dry-run when ready to apply. You can also run the commands below from a reviewed release checkout as the controller user. The updater downloads the selected stable release directly from GitHub. The existing app directory is upgraded in place.

bash update.sh --check
bash update.sh --release '<stable-tag>' --expect-commit '<full-commit>' --url https://hp6033a.local --dry-run
bash update.sh --release '<stable-tag>' --expect-commit '<full-commit>' --url https://hp6033a.local

Use the controller's actual HTTPS URL. By default the health check trusts the installed self-signed certificate. Pass --ca-cert with the trusted CA file if the site uses another certificate. The check connects to this Pi over loopback and validates the supplied hostname or IP.

Review the preview before applying. Close both dashboards, leave the supply connected with output off, and disable remote programming. The updater checks these conditions and reads status over HTTPS. It backs up the application and system files privately and restarts only the controller service. The Nginx site, TLS material, credential policy, and systemd unit stay in place. A failed activation triggers rollback.

The older one-worker Pi 3 layout is supported when its unit, Unix socket, HTTPS site and credential format pass the compatibility checks. The updater can preserve a legacy VISA resource stored as a literal in the app. If the old Nginx site still controls authentication, the updater retains that policy. To move to dashboard-managed authentication separately after verifying the upgrade, use the existing command below.

sudo bash ~/hp6033a/deploy/set-control-auth.sh dashboard

Reload the page and open Setup in Modern or Setup & Extra Controls in Classic.

Verification script

After installation, reconnect the USB adapter to apply the udev rules and open a fresh SSH session. Save the block below as verify.sh. Run it from a trusted client with Bash, curl and Python 3. Add --require-gpib during commissioning with the adapter and supply connected. Use a trusted certificate, or point curl to a verified copy of the controller certificate with CURL_CA_BUNDLE.

#!/usr/bin/env bash
set -euo pipefail
base=${1:?Usage: verify.sh https://PI_ADDRESS [--require-gpib]}
case "$base" in https://*) ;; *) echo "Use the HTTPS URL" >&2; exit 2;; esac
base=${base%/}
for route in / /classic-dual /docs/ /static/docs/project.html \
    /static/docs/commands.html /static/docs/installation.html \
    /static/docs/recovery.html; do
  curl -fsS --max-time 10 -o /dev/null "$base$route"
  printf 'OK %s\n' "$route"
done
curl -fsS --max-time 25 "$base/api/status" | python3 -c '
import json, sys
data = json.load(sys.stdin)
print("Mode:", data["mode"])
print("GPIB:", data["gpib_status"])
if sys.argv[1] == "--require-gpib" and not data["gpib_connected"]:
    raise SystemExit(1)
' "${2:-}"

The script performs GET requests and reports GPIB status. With output off and the load disconnected, compare reported measurements and setpoints against the physical panel. Test hardware control separately with the supply attended.
