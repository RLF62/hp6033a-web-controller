Prepare the OS and staging folder

  1. Use Raspberry Pi Imager to write Raspberry Pi OS Lite (64-bit, Debian 13 baseline) to a spare microSD card. Set up Wi-Fi, SSH, a hostname and the pi account. The existing controller uses hp6033a and 192.168.1.100. Give the spare Pi a different reserved address while both are online.
  2. Connect over SSH and check uname -m for aarch64. The inspected deployment used Python 3.13.5.
  3. On the new Pi, prepare a staging folder outside /home/pi/hp6033a. Copy app.py, requirements-backup.txt, templates/, docs/, and static/ from a known-good source or backup. Include config.json if you need saved presets.
  4. Copy /etc/systemd/system/hp6033a.service, /etc/nginx/sites-available/hp6033a, and /etc/udev/rules.d/99-usbgpib.rules from the release into staging as systemd.service, nginx.conf, and usb.rules.

The older install.sh found on the working Pi configures the retired simulation layout. Use the current unit, nginx site, and installation sequence below.

Prepare site configuration and credentials

  • systemd. Keep the application directory, one Gunicorn worker, the pi:www-data service identity, and the socket at /run/hp6033a/gunicorn.sock.
  • nginx. In the staged site configuration, update the HTTPS redirect, permitted subnet and exact control Origin for the new Pi. Keep Basic authentication on /api/control/ and the Unix socket upstream.
  • TLS. Provision a matching certificate and private key as /etc/nginx/ssl/hp6033a.crt and /etc/nginx/ssl/hp6033a.key. Set the private key to root ownership and mode 0600. The certificate must cover the HTTPS address and be trusted by the browser. For an IP URL, include an IP subject alternative name. Keep the private key outside the release archive.
  • USB. The deployed rule grants plugdev access to the USB device and its USBTMC node for adapter ID 03eb:2065. Confirm the replacement adapter ID with lsusb and update the rule only if required. Match the discovered USB VISA resource to GPIB_RESOURCE in app.py.

The installer creates a bcrypt controller credential interactively and copies the record into the separate Flask and nginx password files. The credentials are separate from SSH.

The pinned versions come from requirements-backup.txt. Direct dependencies recorded on the working Pi include Flask 3.1.3, Gunicorn 26.2.0, PyVISA 1.16.2, PyVISA-py 0.8.1, PyUSB 1.3.1, pyserial 3.5, and bcrypt 5.0.0.

Fresh installation script

Copy this block to install-fresh.sh and run it as pi with the prepared staging folder's absolute path. Use it on a dedicated fresh Pi. A failure can leave a partial installation. Review the failed step before retrying. This script has not been executed on a fresh Pi.

#!/usr/bin/env bash
set -euo pipefail
app=/home/pi/hp6033a
stage=${1:?Usage: install-fresh.sh /path/to/prepared-staging}
[[ $(id -un) == pi ]]
[[ ! -e "$app" ]]
[[ ! -e /etc/systemd/system/hp6033a.service ]]
[[ ! -e /etc/nginx/sites-available/hp6033a ]]
[[ ! -e /etc/nginx/sites-enabled/hp6033a ]]
for file in app.py requirements-backup.txt systemd.service nginx.conf usb.rules; do
  [[ -f "$stage/$file" ]]
done
for dir in templates docs static; do [[ -d "$stage/$dir" ]]; done
sudo test -s /etc/nginx/ssl/hp6033a.crt
sudo test -s /etc/nginx/ssl/hp6033a.key
sudo apt-get update
sudo apt-get install -y python3-venv nginx apache2-utils \
  openssl libusb-1.0-0 usbutils curl
install -d -m 0755 "$app"
cp -r -- "$stage"/{app.py,requirements-backup.txt,templates,docs,static} "$app/"
if [[ -f "$stage/config.json" ]]; then
  install -m 0600 "$stage/config.json" "$app/config.json"
fi
cd "$app"
python3 -m venv venv
venv/bin/python -m pip install -r requirements-backup.txt
venv/bin/python -m pip check
venv/bin/python -c 'import flask, gunicorn, pyvisa, usb, serial, bcrypt'
(umask 077; htpasswd -B -c .control_htpasswd hpcontrol)
sudo install -o root -g www-data -m 0640 \
  .control_htpasswd /etc/nginx/hp6033a.htpasswd
sudo usermod -aG plugdev,dialout pi
sudo install -m 0644 "$stage/usb.rules" /etc/udev/rules.d/99-usbgpib.rules
sudo udevadm control --reload-rules
sudo install -m 0644 "$stage/systemd.service" /etc/systemd/system/hp6033a.service
sudo install -m 0644 "$stage/nginx.conf" /etc/nginx/sites-available/hp6033a
if [[ -L /etc/nginx/sites-enabled/default ]]; then
  sudo unlink /etc/nginx/sites-enabled/default
fi
sudo ln -s /etc/nginx/sites-available/hp6033a /etc/nginx/sites-enabled/hp6033a
sudo nginx -t
sudo systemctl daemon-reload
sudo systemctl enable --now hp6033a nginx
sudo systemctl reload nginx

Verification script

After installation, reconnect the USB adapter to apply the udev rules and open a fresh SSH session. Save the block below as verify.sh. Run it from a trusted client with Bash, curl and Python 3. Add --require-gpib during commissioning with the adapter and supply connected.

#!/usr/bin/env bash
set -euo pipefail
base=${1:?Usage: verify.sh https://PI_ADDRESS [--require-gpib]}
case "$base" in https://*) ;; *) echo "Use the HTTPS URL" >&2; exit 2;; esac
base=${base%/}
for route in / /classic-dual /docs/ /static/docs/project.html \
    /static/docs/commands.html /static/docs/installation.html \
    /static/docs/recovery.html; do
  curl -fsS --max-time 10 -o /dev/null "$base$route"
  printf 'OK %s\n' "$route"
done
curl -fsS --max-time 25 "$base/api/status" | python3 -c '
import json, sys
data = json.load(sys.stdin)
print("Mode:", data["mode"])
print("GPIB:", data["gpib_status"])
if sys.argv[1] == "--require-gpib" and not data["gpib_connected"]:
    raise SystemExit(1)
' "${2:-}"

The script performs GET requests and reports GPIB status. With output off and the load disconnected, compare reported measurements and setpoints against the physical panel. Test hardware control separately with the supply attended.
